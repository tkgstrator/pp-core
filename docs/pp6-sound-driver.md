# PP6（BP6J）サウンドドライバー解析

ROM `pp6_v0_clean.gba`（SHA-256 `65f994ec…6003e`）のBGM再生系を、実機どおりに鳴らせるように再実装する目的で解析した記録。アドレスはすべてGBAアドレス（`0x08xxxxxx`はROM）。

検証用の参照実装（Python）は `docs/pp6-sound-driver/model.py` にある。エミュレータ（mGBA libretro）で各フレームのドライバー内部状態を記録し（`trace.py`）、モデルと突き合わせた（`compare.py`）。結果は「検証」の節を参照。

## 全体構成

| 層 | 内容 |
|---|---|
| コナミ製シーケンサー（`0x0800f000`〜`0x08012d4c`） | 楽譜バイトコードを読み、PSGはGBサウンドレジスターへ直接書き、PCMはm4aのSoundChannelを書く |
| 任天堂MP2K（m4a）ミキサー（`0x080f7xxx`、SoundInfo `0x03005700`） | PCMを21,024 Hzでソフトウェアミックスし、DMA1/2でFIFO A/Bへ送る。m4aのシーケンサー部分（MPlay）は使っていない |
| GB PSG（ハードウェア） | 矩形波1・2、波形メモリ、ノイズ |

- シーケンサーの割り込みはタイマー2（`TM2CNT=0xc1`、リロード`0xfbe7`）。16777216 / 64 / 1049 ≈ 249.90 Hz。
- 1回の割り込みで4つの「相」のうち1つを処理するので、各トラックの更新は62.4747 Hzになる（pp-extractの`DRIVER_UPDATE_HZ`と同じ）。
- m4aの`SoundMain`は別系統で、VBlank（59.73 Hz）ごとに1回。

## 1. メイン更新とリクエスト

### 割り込みハンドラー `0x080103f4`

1. 再入防止：`0x03004830`のbit5が立っていれば何もせず戻る（カウンターも増えない）。
2. `0x02017060`を`0x020004b4`へコピーする（ポーズ中フラグ。0以外ならcategory 1のトラックは止まる）。
3. `phase = G.counter & 3`（`G = 0x03000160`、`G+0x04`がu32カウンター）で処理を分ける。
   - **相0**
     1. 一時停止中でなければリクエストキューを処理する（`0x0800f1f8`）。
     2. フェード処理：`0x080104c4`（フェードイン）、`0x08010594`／`0x0801067c`（SE用のSOUNDCNT_L音量操作）、`0x080106ec`（フェードアウトとテンポ変化）。
     3. PCMスロット0〜2の更新。
   - **相1**：PCMスロット3〜6の更新（`0x08010800`）
   - **相2**：PSGスロット0〜2の更新（`0x0801085c`）
   - **相3**：PSGスロット3〜5の更新（`0x080108ac`）、その後`0x0801048c`。
4. 最後に`G.counter += 1`。

スロットの更新は「`id != 0`」かつ「ポーズ中にcategory 1でない」ときだけ行う。ディレイカウンター（PSGは`+0x16`、PCMは`+0x04`）が0でなければ1減らすだけで終わる。BGMのディレイは常に0。

### リクエストキュー

- `G+0x09`（`0x03000169`）が件数、`G+0x0a`（`0x0300016a`）からがu16のIDの配列。
- 相0で先頭から処理する（`0x0800f1f8`）。
- **ID ≤ 0x3f：コマンド**（ハンドラー表 `0x0855e328`）

  | ID | 処理 |
  |---|---|
  | 0,1 | 全停止 `0x0800fd60` |
  | 2 | BGM停止 `0x0800fdcc` |
  | 3 | 一時停止 `0x0800fef0`（`G+0x2b=1`） |
  | 4 | 再開 `0x0800ff50` |
  | 8〜10 | BGMフェードアウト `0x080100ec`（速さは`0x0855e31c`の3/5/7） |
  | 11〜13 | `0x08010038` |
  | 14,15 | テンポ加算`G+0x32`の増減ランプ（`0x080102fc`／`0x08010354`） |

- **0x40 ≤ ID ≤ 0x1ff：BGM**。`0x0800f564(id, category=1)` を呼ぶ。
- **ID ≥ 0x200：SE**。category 2。
- 特殊なID（`0x0800f3b8`、`0x0800f438`）
  - `0x4b`：`0x4f`を止め、`G+0x42=1`にしてから再生する。
  - `0x59`：`0x80109dc`を呼ぶ。
  - `0x7d`：`0x8010910(3,3,0)`の後、IDを`0x7c`に書き換えて再生する。
  - `0x4e`／`0x7d`／`0x236`／`0x23d`／`0x2ef`／`0x359`：それぞれ追加の処理がある。
  - `0x32c`：乱数で別IDを選ぶ（`0x0800f51c`）。

### BGM開始 `0x0800f564`

- **ディスクリプター**：BGM表は`0x08135c0c + id*12`、SE表は`0x0813a568 + id*12`。
  - `+0` u32 `flags`
  - `+4` u16（下位バイトが`priority`）
  - `+8` u32：トラックが1本ならそのストリームへのポインター、複数ならポインター配列へのポインター。
- **トラック数**：`popcount(flags & 0x3f) + popcount((flags>>8) & 0x7f)`。
- 開始前に同じIDのトラックを止め（`0x0800f1ac`）、category 1ならBGMをリセットする（`0x0800fdcc`）。リセットでは次を行う。
  - `SOUNDCNT_L=0`の後に`0x77`。
  - `G.0x2d=0`。
  - category 1のPSGスロットをすべてkill（`0x0800fe84`）。
  - category 1のPCMスロットをすべてkill（`0x08010958`）。
- **リクエスト構造体** `0x030001ac`：`+0` id、`+3` priority、`+4` category、`+5` delay=0、`+6` param=0。
- **ポインター配列はフラグの「ビット順」で前から消費する**（`0x0800f9f8`、`0x0800fb34`）。

| flagsのbit | 割り当て先 | 備考 |
|---|---|---|
| 0x0001 | PSGスロット0（矩形波1） | 先に`NR10=8`を書く。SOUNDCNT_Lに`0x1100`をOR |
| 0x0002 | PSGスロット1（矩形波2） | `0x2200` |
| 0x0004 | PSGスロット2（波形メモリ） | `0x4400` |
| 0x0010 | PSGスロット3（コントロール／ドラム） | `0x8800` |
| 0x0008 | PSGスロット5（ノイズ） | `0x8800` |
| 0x0100〜0x4000 | PCMスロット0〜6 | |

PSGスロット4は「SEが矩形波1を使うとき」専用（`0x0800f7e8`）で、BGMでは使わない。

### スロット初期化

- **PSG**（`0x0800fc50`）
  - `+12` id、`+14` priority、`+16` delay、`+18` cursor、`+10` category
  - `+1c=0x80`、`+1e=0x80`（テンポ）、`+1f=1`（待ち）、`+78=0`、`+20 = +00`（パン＝全出力）、`+22=param`、`+26=+28=0`
  - `+2a`〜`+2f=0`、`+23=0`、`+5a`／`+5b`／`+5c`／`+5e=0`
- **PCM**（`0x0800fcd0`）
  - `+0` id、`+2` priority、`+4` delay、`+8` cursor、`+13` category
  - `+0c=0x80`、`+0e=0x80`、`+0f=1`、`+10=10`（パン中央）、`+12=1`（ゲート）、`+16=+18=0`
  - `+1a=0xff`（音量）、`+1b`／`+1c`／`+1d=0`、`+1e=0xff`（アタック）、`+1f=0`、`+14=+15=0`
  - `+68`／`+6a`／`+72`／`+74`／`+6c`／`+76`／`+78`／`+7a`／`+4a`／`+4c`／`+4e`／`+50=0`

## 3. 1トラックのtick

### PSG（`0x08010f18`）

```
G.3b=0; G.3c=0
G.3a = (slot.type==0 && PSG[4].id!=0)
ph = (ph16 + tempo + (category==1 ? G.32 : 0)) & 0xffff
if ph <= 0xff:  ph16=ph; wave_release(); freq_update(); return     # 行なし
ph16 = ph - 0x100; wait -= 1                                          # 行
if wait != 0: step()  else: cursor = interp(cursor)
```

`step()`（`0x0801131c`）：

```
if silent(+70): return
if porta_delay(+2b): if --porta_delay == 0: pitch(+38) += s8(+36)<<8; G.3b=1
if gate(+3c):  if --gate == 0:  # キーオフ
    wave:   if rel(+2f)==0 && relcnt(+31)==0: silent=1; soundcnt(0); return
            relcnt = rel; wave_release()
    other:  if G.3a: return
            NRx2/NRx1 = rel ? (vol<<12 | rel<<8 | read(NRx1/2)) : read(NRx1/2) & 0xc0
            G.3c = 0x8000          # この後のfreq_updateでトリガーし直す
freq_update()
```

- キーオフのとき、矩形波とノイズはハードウェアのエンベロープ（減少方向、周期=rel、1/64秒単位）に任せて、トリガーし直す。rel=0なら音量0でトリガーして即座に無音になる。
- 波形メモリ（`0x08011410`、wave_release）は、行のないtickでだけ`relcnt`を減らす。0になるたびに`vol -= 1`としてNR32を書き直し、`relcnt = rel`に戻す。`vol==0`になったら`silent=1`。

`freq_update()`（`0x08011480`）：

```
f = +38
if porta_delay != 0: +34 += +32; f += +34; G.3b=1          # 遅延の間だけスライドする
if vib_depth(+2c): vibrato(); f += +40
if lfo2(+2d):      lfo2();    f += +48
if !G.3a && (G.3b || G.3c): freq_write(f)
```

`freq_write(f)`（`0x0801125c`）：

- `semi = (f>>8)&0x7f`、`frac = f&0xff`。
- **ノイズ**：`NR43/44 = NOISE[semi] | +23 | G.3c`。
- **それ以外**：`period = (PERIODS[semi] + ((PFRAC[semi]*frac)>>8)) & 0x7ff`。
  - `NRx3/4 = period | G.3c`。
  - 続けて`NRx1/2 |= +23`（デューティーを戻す）。

| 表 | アドレス |
|---|---|
| PERIODS | `0x080fbab4` u16[128] |
| PFRAC | `0x080fbbb4` u8[128] |
| NOISE | `0x080fbc34` u8[128] |

### PSGインタープリター（`0x08010fc0`）

- `+2b = 0` にする。
- 0x80以上のバイトはハンドラー（表`0x0855e374`の`[op-0x80]`）で処理する。`d9`／`c0`／`e3`のときは行を終える。
- 0x80未満なら音符として処理し、行を終える。

**音符 `op < 0x80`**

1. `+31 = 0`、`silent = 0`。
2. オペランドを順に読む。
   - `op & 0x10` が0なら gate（`+3b`）を読む。その後 `+3c = +3b`。
   - `op & 0x20` が0なら wait（`+3a`）を読む。その後 `+1f = +3a`。
   - `op & 0x40` が0なら音高（`+37`）を読む。
3. コントロールトラック（type 3）ならドラム（後述）を起動して終わる。
4. 音量：`v = s8(nib - +2a - +22 + +5a + +5b)`。
   - `v < 0` なら `v = 0`、`silent = 1`。
   - `v > 15` なら `v = 15`。
5. `+30 = v`。`!G.3a` なら `set_vol(v)` を呼ぶ。
6. ビブラートが有効なら `+3e = +3d`、`+42 = +45 = +40 = 0`。
7. `+38 = (s8(+37)<<8) + +26 + +28 + +5c + +5e`。`!G.3a` なら `freq_write(+38)` を呼ぶ。

`set_vol(v)`（`0x080111e4`）：

- **波形**：`v` を0..4に収める（範囲外は4）。
  - `NR32 = WAVE_VOL[v]`（`0x0813d36c`：`{0, 0x6000, 0x4000, 0x8000, 0x2000}` ＝ 無音、25%、50%、75%、100%）。
  - 続けて `soundcnt(+20)`。
- **その他**：
  - `x = read(NRx1/2) & 0xc0`。
  - `x |= (+2e & 0x40) ? +2e<<8 : v<<12`。
  - これを書き、`G.3c = 0x8000`。

`soundcnt(x)`：`!G.3a` のとき `G.3e = (G.3e & ~slot.mask) | x` として SOUNDCNT_L に書く。

### PCM（`0x08011f9c`）

```
G.3b=0; G.3c=0; fades()
ph = ph16 + tempo + (category==1 ? G.32 : 0)
if ph <= 0xff: ph16=ph; freq_update(); return
ph16 = ph - 0x100; wait -= 1
if wait: step() else interp()
set_volume(+25)                         # 行ごとに書く
```

`step()`（`0x080124a0`）：

```
if rest(+64): return
if porta_delay(+1b): if --porta_delay == 0: +28 += s8(+24)<<8; G.3b=1
if gate(+2d):  if --gate == 0: ch.release = +1f; ch.status |= 0x40
freq_update()
```

- `freq_update()`（`0x08012520`）はPSGと同じ形だが、オフセットが`+28`／`+22`／`+20`／`+32`／`+3a`になる。`G.3b` のときだけ `set_freq(f)` を呼ぶ。
- `set_freq(f)`（`0x08012470`）：
  - `x = (f + 0x1800) & 0xffff`。
  - `ch.freq = MidiKeyToFreq(ch.wav, (x>>8)&0x7f, x&0xff)`。
  - これはm4aの`0x080f83f0`で、標準と同じ実装。key>178なら178、fine=255にする。
  - 表はScale `0x08554408`、Freq `0x085544bc`。
  - 計算：`val = v1 + umulH(v2-v1, fine<<24)`、`freq = umulH(wav.freq, val)`。

### PCMインタープリター（`0x08012150`、表`0x0855e5b4`）

**音符**

1. キーオンの判定：`retrig = rest ? 1 : old_gate(+12)` を先に決めてから、`rest = 0` にする。
2. オペランドを順に読む。
   - `op & 0x10` が0なら gate（`+12`）を読む。その後 `+2d = +12`。
   - `op & 0x20` が0なら wait（`+2c`）を読む。その後 `+0f = +2c`。
   - `op & 0x40` が0なら音高（`+26`）を読む。
3. 音量：`v = ((nib*8 + s16(+4a) + s16(+4c)) * +1a)` を `[0, 0x7fff]` に収める。
   - 負なら `rest = 1`。
   - `+25 = v >> 7`。
4. 音高の分岐
   - `+26 > 0x4f`：PCMドラム。`(+14, +2a) = PCM_DRUMS[+26-0x50]`（`0x0855e318`）、`ch.wav = bank0[+14]`、`+26 = 0x18`。
   - それ以外でビブラートが有効なら、ビブラートをリセットする。
5. `+28 = (s8(+26)<<8) + +2a + +16 + +18 + +4e + +50`。`set_freq(+28)` を呼ぶ。
6. `retrig` なら：`ch.attack = +1e`、`ch.decay = 0xff`、`ch.sustain = 0xff`、`ch.release = 0xff`、`ch.status = 0x80`（キーオン）。
   - `retrig == 0`（前のgateが0）なら、レガートとして音高だけ変わる。

`set_volume(v)`（`0x08012370`）：

- 左：`ch.leftVol(+3) = v*PAN[p]>>8`。
- 右：`ch.rightVol(+2) = v*PAN[20-p]>>8`。
- `p = +10`、`PAN = 0x0813d386` = `255,242,229,…,12,0`（21要素）。
- フェード（`+68`／`+70`／`+7a`／`+7e`）が有効なら、さらに `*k>>4` を掛ける。

サンプルの選択（`0x0801259c`）：

- `ch.wav = 0x08722da8 + u32[u32[0x0855e2a0 + 4*bank] + 4*index]`。
- バンク0（`0x0855df6c`）なら `+2a = TRANSPOSE[index]`（s16、`0x0855e2a8`）。それ以外は0。

### 繰り返し（f3/f4）

1. `n != 0` のとき、`count++` する。
   - `count == n` になったら、`dv`/`dp` を読み飛ばし、音量と音高の増減を0に戻して抜ける。
2. それ以外（`n == 0` を含む）では次を行い、戻り先へジャンプする。
   - `dv != 0` なら音量の増減に足す（PSGは±15、PCMは±255に収める）。
   - `dp != 0` なら音高の増減に `s8(dp)<<3` を足す。
3. `n == 0` は無限ループ（曲の終わりのループ）。

### 波形の書き換え（`d1`、type 2）

1. `NR30 = 0x40`（バンク1を再生、CPUはバンク0へ書く）。
2. 波形RAM `0x04000090` に `WAVES[b]` の16バイトを書く（`0x080fbd34 + b*16`）。
3. SOUNDCNT_L から ch3 を外す（`&0xbbff`）。
4. `NR30 = 0x80`（バンク0を再生、32サンプル）。
5. `NR33/34 |= 0x8000`（トリガー）。

## 5. 時間変化する効果

- **ビブラート**（PSG `0x080116bc`、PCM `0x080125f8`）。毎tick次を行う。
  1. `(G.counter & 0xc) == 0` かつ ランプ≠0 かつ 倍率≠0 なら、`倍率 += ランプ`。0xffを超えたら0にする（以後は深さそのままになる）。
  2. `累積 += 速さ`。0xffを超えたら次を行う。
     1. `累積 &= 0xff`。
     2. `d = 倍率 ? (深さ*倍率)>>8 : 深さ`。
     3. `位置 += step`。
     4. `出力 = VIB[位置&15]*d`。`位置&0x10` が立っていれば符号を反転する。
     5. `G.3b = 1`。
  - `VIB = 0x0813d376` = `0,4,7,9,11,12,13,14,15,14,13,12,11,9,7,4`。
  - 音符ごとに倍率をランプ値にリセットする（ディレイビブラート）。
- **LFO2**（`0x08011640`／`0x080126ac`）
  - `累積 += 速さ`。0xffを超えたら次を行う。
    - `位置 = (位置+1) & 0x7f`。
    - `出力 = u16le(LFO2TAB[位置]) & マスク`。`LFO2TAB = 0x080fbcb4`。
  - 音符ではリセットしない。
- **ポルタメント（e1/e2）**：`porta_delay != 0` の間は毎tick `累積 += 増分`。
  - 行ごとに遅延を減らし、0になった行で `pitch += s8(jump)<<8`。
  - 新しい行の音符では累積を0にしない（e2でだけ0になる）。
  - インタープリターの入口で毎回 `porta_delay = 0` にする。つまり **e1は、その行の音符にだけ効く**。
- **ゲートとリリース**：上記の`step()`のとおり。
  - gateは「waitが0にならなかった行」でだけ減る。
  - gate ≥ wait なら、次の音符までキーオフしない。

## 6. ドラム（コントロールトラック type 3）

- コントロールトラックの音符（`0x08011164`）は、次の場合に何もしない。
  - `PSG[5].id > 0x3f`（ノイズをSEが使用中）。
  - `pitch < 0x50`。
- それ以外では次を行う。
  1. `silent = 1`。
  2. `SOUNDCNT_L |= 0x8800`。
  3. PSGスロット5を初期化する。
     - id 0x0f、priority 0、category 2、delay 0。
     - `param(+22)` = 呼び出し元の音符の下位ニブル。
     - stream = `u32 [0x0855e574 + 4*(pitch-0x50)]`。
- ドラムのサブトラックは、ノイズチャンネルとして通常のPSGインタープリターで動く。
  - 音量は `nib - +2a - param`。
  - 周波数は `NOISE[semi] | +23`。
- BGMのノイズトラック（flags bit3）と同じスロット5を取り合う。後から始まった方が上書きする。

## 7. 出力段

### PSG（ハードウェア）

- レジスター
  - `SOUNDCNT_H = 0x210d`：PSGは50%、FIFO Aは100%で右、FIFO Bは100%で左、どちらもタイマー0。
  - `SOUNDBIAS = 0x200`。
  - `SOUNDCNT_L`：音量7/7と、上のイネーブルビット。
- 矩形波
  - NRx1のlength=0、NRx4のlength enable=0。
  - エンベロープ：キーオンは周期0（一定）。キーオフは減少方向、周期=rel。
- 波形メモリは32サンプル1バンク。
- ノイズ：NR43は表から、幅はbit3。
- mGBA libretro（65,536 Hz、int16）で測った値。
  - PSG：`48 × (master+1) × Σvol`（50%時、片側。PSGは0か正の値だけで、DCを含む）。
  - FIFO：`192 × sample8`。
  - 10bit DACの単位では、PSG＝`vol×(master+1)`、FIFO＝`sample×4`。

### PCM（m4a SoundMain、`0x080f77e4`、ARMのミックス部は`0x03006841`のIWRAMにコピーされる）

SoundInfo の主な値

| 項目 | 値 |
|---|---|
| ident | `'Smsh'` |
| reverb | **0**（バッファーはゼロクリアだけ） |
| maxChans | 7 |
| masterVolume | 14 |
| freq index | 7（21,024 Hz。`pcmFreq = 0x5220`） |
| pcmSamplesPerVBlank | 352 |
| divFreq | 399 |
| pcmDmaPeriod | 4 |

- バッファーは `SoundInfo+0x350` が右（FIFO A）、`+0x980` が左（FIFO B）。
- タイマー0のリロードは `0xfce2`（798サイクル＝21,024 Hz）。

**エンベロープ（VBlankごと。チャンネル構造体 +0 status、+2 rightVol、+3 leftVol、+4 attack、+5 decay、+6 sustain、+7 release、+9 envVol、+0xa envR、+0xb envL）**

1. **キーオン**（`status&0x80`）
   - stopも立っていれば `status = 0`。
   - そうでなければ次のとおり。その場でattackの段に入る（attack=0xffなら即座に255、status=2）。
     - `status = 3`（サンプルのループフラグ `wav[3]&0xc0` があれば `|0x10`）
     - `pos = wav+0x10`、`count = wav.size`、`env = 0`、`fw = 0`
2. **リリース**（`0x40`）：`env = env*release>>8`。`env ≤ echoVol` になったら、`env = echoVol`。0なら`status = 0`、そうでなければecho（`|4`、`+0xd`の長さだけ鳴らす）。
3. **decay**（status 2）：`env = env*decay>>8`。`env ≤ sustain` なら `env = sustain`、`status--`（sustainが0なら停止）。
4. **attack**（status 3）：`env += attack`。`≥0xff` なら `0xff`、`status--`。
5. 音量：`vol = (masterVolume+1)*env >> 4`。
   - `envR = rightVol*vol >> 8`。
   - `envL = leftVol*vol >> 8`。

**再サンプリング**

- PP6の全チャンネルは `type=0`（固定周波数ではない）なので、**線形補間**のパス（`0x080f7b40`）を通る。
- `step = divFreq * ch.freq`。位置の小数部は23bit（`lr`）。
- 各出力サンプルで次を計算する。
  - `s = s0 + ((lr*(s1-s0)) >> 23)`。
  - 右：`acc_R = ror(acc_R, 8) + (envR*s & ~0xff0000)`。左も同じ（envL）。
  - accは出力バッファーの4バイトを1語にしたもので、4サンプルごとに保存する。結果は8bitで回り込む（クリップしない）。
- サンプルの終わり
  - ループするなら `loopStart`（`wav[8]`）へ戻る。
  - ループしないなら `status = 0`。

## 8. 検証

`trace.py` は、メニューでBGMリクエストをキューに入れ、毎ビデオフレームごとに次を保存する。

- IWRAM `0x03000160..0x03000950`
- SoundInfo `0x03005700..0x03005a50`
- IO `0x04000060..0x040000a0`

`compare.py` は、記録した直前の状態からモデルを動かし、割り込みカウンターに合わせてフレームごとに比べる。比べる範囲は次のとおり。

- PSG/PCMスロットの全バイト
- m4aチャンネルの `+2,+3,+4,+7,+0x20..0x27`
- 読み出せるIOビット
- `G+0x2a..0x43`

結果

| 対象 | 結果 |
|---|---|
| BGM 0x68／0x6a／0x81（各1800フレーム、30秒） | 3連続フレーム以上続く不一致は0件 |
| PP6の全150曲（各1500フレーム、25秒） | 148曲で不一致0件。残り2曲は既知の特殊処理（`0x4b`は`G+0x42=1`、`0x7d`はIDを`0x7c`に書き換え）だけが違う |
| 1フレームだけの不一致（全体の約1%） | スナップショットがタイマー割り込みの途中に入った状態（トラックは更新済み、カウンターは未更新）。次のtickと一致する |
| m4aのエンベロープ（`envchk.py`、60曲） | 184,590件中184,044件が一致。残りはサンプル末尾での停止（status 0）と、フレーム途中のドライバー書き込み |

全BGMで実際に使われていたオペコード（すべて検証済み）

- PSG：80–87, 89–8b, 8d, 8e, 90, 94–9f, a6–b0, c0–c6, d0, d4, d5, d9, e1–e3, f1, f3, f4
- PCM：c0–c6, d0–d6, d9, e1–e3, f1, f3, f4

## 未検証・注意点

1. **書き込み専用レジスターの実際の書き込み値**：NRx3/x4の周波数とトリガーは、mGBAのメモリーからは読めない。PSGの周期値は、構造体の音高`+38`（一致を確認済み）と表引きの式から導いたもので、レジスター上では確かめていない。pp-extractの`psg_period`は同じ表を使っていて、ドライバーのトレースで確認済みとされる。
2. **BGMでは未使用で、逆アセンブルだけから書いたオペコード**：d3（PSG）、d8、da、db、dc（PSG）、e0、f0、f2、f5、f6、d7、PCMの80–95、96–a5、a6–ad、ae–b0、dc。
3. **PCMドラム表** `0x0855e318`：フェード速度の表`0x0855e31c`と重なっていて、実質1件か未使用と思われる。BGMで`pitch>0x4f`のPCM音符があるかは確認していない。
4. **m4aのミックスループ**：`acc`へのバイト単位の加算、FIFOの丸め、echo、固定周波数のパスは逆アセンブル（標準のm4a_1.sと同じ）に基づく。PCMバッファーの中身とビットまで一致するかは確かめていない。
5. **ハードウェアの合成比率**：mGBAでの実測値。実機のアナログ段（PSGのDCやハイパス）は含まない。
6. **タイミング**：ドライバーは249.9 Hzを4相に分けて動き、m4aは59.73 Hz（VBlank）で動く。ドライバーの書き込みがどのVBlankで反映されるかは割り込みの位相で決まる。正確に再現するにはサイクル単位の時刻（タイマー2とVCOUNT）が要る。
7. **SE、一時停止、フェード、テンポランプ、矩形波1のSEからの復帰**（`0x080117a4`）は概要だけで、照合していない。
